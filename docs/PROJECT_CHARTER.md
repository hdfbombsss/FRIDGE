# Устав проекта

## Цель

Помочь пользователю выбрать блюдо из имеющихся продуктов без ручного перебора рецептов.

## Пользователи и сценарий

Домашний пользователь указывает продукты и, при необходимости, количество. Сервис показывает рецепты, для которых продукты уже есть, а затем варианты с недостающими ингредиентами. Из выдачи пользователь открывает состав и шаги приготовления.

## Минимальный результат

1. Пользователь добавляет и удаляет ингредиенты.
2. Поиск работает на небольшой проверенной базе рецептов.
3. Выдача различает подходящие рецепты и варианты с недостающими продуктами.
4. Карточка рецепта показывает состав, шаги и недостающие продукты.
5. Ошибки и отсутствие результатов отображаются понятно.

## Границы первой версии

В первую версию не входят регистрация, персональные рекомендации, покупки, генерация рецептов нейросетью и сложные пищевые ограничения. Эти функции можно оценить отдельными Change Request после работающего основного сценария.

## Критерии приёмки

- Для заранее согласованного набора ингредиентов выдача воспроизводима и объяснима.
- Если рецепт требует отсутствующий продукт, он явно указан как недостающий.
- Пустой запрос, отсутствие совпадений и ошибка получения данных не ломают интерфейс.
- Основной сценарий проходит проверку QA на тестовом стенде; найденные дефекты заведены и исправления подтверждены.

## Ограничения и решения команды

Команда состоит из четырёх человек. PM совмещает управление с ограниченными фронтенд-задачами. Сковороднев отвечает за backend, техническое руководство и DevOps; Ярмов — за аналитику, QA и UI/UX-дизайн. Стек, источник рецептов, точная трактовка количества продуктов и тестовый хостинг утверждаются командой до реализации соответствующих задач. Внешний API допускается только после проверки лицензии, лимитов и стабильности; локальная проверенная выборка остаётся запасным вариантом.
